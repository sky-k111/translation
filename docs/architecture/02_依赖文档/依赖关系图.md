## 1. 依赖关系概述

本文件描述了单词翻译助手插件各模块之间的依赖关系，用于指导重构工作和理解代码结构。

### 项目特点
* **无构建工具**: 原生Chrome扩展，代码直接运行，无需bundler或transpiler
* **模块化架构**: 清晰的模块分层，易于维护和扩展
* **组件系统**: BaseComponent继承模式，统一的生命周期管理
* **多层缓存**: 内存缓存 + 持久化存储，性能优化
* **服务降级**: 翻译服务自动fallback链（AI → 网易 → MyMemory → 百度）
* **CSP合规**: Manifest V3严格CSP策略，所有资源本地化

## 2. 模块分类

### 核心模块（Extension Entry Points）
- **core/background.js** - 后台服务工作进程（Background Service Worker）
  - 职责：API调用、消息处理、跨标签页通信、页面导航监听
  - 依赖：services, config, utils, components/background
  - 权限：chrome.runtime, chrome.storage, chrome.webNavigation, chrome.tabs
  
- **core/content.js** - 内容脚本（Content Script）
  - 职责：页面交互、文本选择、翻译请求、高亮显示、DOM操作
  - 依赖：services, utils, modules, components/content
  - 权限：DOM操作、chrome.runtime.sendMessage、chrome.storage
  - 加载顺序：manifest.json中定义的脚本加载顺序
  
- **core/content.css** - 内容脚本样式
  - 职责：高亮、弹窗、浮动元素的样式
  - 特点：样式隔离，避免与网页样式冲突

### 数据流（Data Flow）

#### 场景1：用户选中文本进行翻译

```
用户在网页上选中文本 "hello"
    ↓
Content Script: handleTextSelection()
    ├─ 检查缓存（内存缓存）
    ├─ 如果缓存未命中
    │  ↓
    │  chrome.runtime.sendMessage({
    │    type: 'SMART_TRANSLATE',
    │    text: 'hello',
    │    context: context
    │  })
    │  ↓
    │  Background: chrome.runtime.onMessage
    │  ↓
    │  Background: smartTranslate()
    │  ├─ 尝试 AI 翻译（如果启用）
    │  │  ├─ 成功 → 返回结果
    │  │  └─ 失败 → 降级到下一个服务
    │  ├─ 尝试 Netease 翻译
    │  │  ├─ 成功 → 返回结果
    │  │  └─ 失败 → 降级到下一个服务
    │  ├─ 尝试 MyMemory 翻译
    │  │  ├─ 成功 → 返回结果
    │  │  └─ 失败 → 降级到下一个服务
    │  └─ 尝试 Baidu 翻译
    │     └─ 返回结果（最后的fallback）
    │  ↓
    │  Background: sendResponse({ ok: true, result })
    │  ↓
    │  Content Script: 接收翻译结果
    │  ↓
    │  Content Script: 缓存结果（内存缓存）
    │
    ├─ 保存到 Chrome Storage
    │  ↓
    │  chrome.storage.local.set({
    │    translatedWords: { hello: {...} }
    │  })
    │
    ├─ 高亮显示
    │  ↓
    │  Content Script: highlightTranslatedWords()
    │
    └─ 显示翻译弹窗
       ↓
       Content Script: showTranslationPopup()
```

```
用户点击扩展图标

popup.js: initializeComponents()

    ├─ 构建搜索索引

    │  └─ 初始化学习面板
    │
    └─ 初始化组件
       ├─ WordDrawer（单词详情抽屉）
       ├─ SearchBar（搜索栏）
       ├─ FilterPanel（筛选面板）
       └─ LearningPanel（学习面板）
```

## 8. 架构设计原则

### 1. 职责分离（Separation of Concerns）

| 组件 | 职责 | 不负责 |
|------|------|--------|
| **Background** | API调用、消息处理、跨标签页通信 | DOM操作、UI展示 |
| **Content Script** | 页面交互、DOM操作、高亮显示 | API调用、密钥管理 |
| **Popup** | UI展示、数据管理、用户交互 | API调用、网页操作 |

### 2. 通信机制（Communication Patterns）

```
Content Script ↔ Background
├─ 方向：双向
├─ 方式：chrome.runtime.sendMessage / chrome.runtime.onMessage
├─ 用途：翻译请求、消息传递
└─ 特点：异步、Promise-based

Background → Content Script
├─ 方向：单向
├─ 方式：chrome.tabs.sendMessage
├─ 用途：重新高亮、页面导航通知
└─ 特点：异步

所有组件 ↔ Storage
├─ 方向：双向
├─ 方式：chrome.storage.local.get/set
├─ 用途：数据持久化、跨会话保存
└─ 特点：异步、事件驱动
```

### 3. 数据流（Data Flow Principles）

```
实时翻译数据流：
用户操作 → Content Script → Background → API → Background → Content Script → UI

数据持久化流：
Content Script → Chrome Storage ← Popup（读取和展示）

学习数据流：
Popup → Chrome Storage → Dashboard（可视化）
```

### 4. 缓存策略（Caching Strategy）

```
多层缓存架构：

┌─────────────────────────────────────────┐
│  内存缓存（Content Script）              │
│  - 翻译结果缓存（500条）                 │
│  - 音标缓存（200条）                     │
│  - 例句缓存（200条）                     │
│  - 释义缓存（200条）                     │
│  特点：快速、易失                        │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  持久化缓存（Chrome Storage）            │
│  - 翻译记录（所有）                      │
│  - 用户设置                              │
│  - 学习进度                              │
│  - 学习历史                              │
│  特点：持久、跨会话                      │
└─────────────────────────────────────────┘
```

### 5. 性能优化（Performance Optimization）

| 优化策略 | 实现方式 | 目标 |
|---------|---------|------|
| 懒加载 | 组件按需加载 | 减少初始加载时间 |
| 虚拟滚动 | VirtualizedTranslationHighlight | 处理大量高亮 |
| 缓存 | 多层缓存系统 | 减少API调用 |
| DOM优化 | 限制高亮单词数（≤50） | 减少DOM操作 |
| 事件优化 | 防抖、节流、事件委托 | 提高事件处理性能 |
| 样式隔离 | 前缀CSS类名 | 避免样式冲突 |

### 6. 安全性（Security）

| 安全措施 | 实现方式 |
|---------|---------|
| CSP策略 | script-src 'self'; object-src 'self' |
| 密钥管理 | API密钥存储在config/api-config.js |
| XSS防护 | Trusted Types策略 |
| 权限最小化 | 仅请求必要权限 |
| 数据隐私 | 所有数据本地存储，无云上传 |
